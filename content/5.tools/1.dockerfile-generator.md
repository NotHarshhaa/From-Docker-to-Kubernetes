## Generator Highlights & Production Best Practices

Creating production-grade containers requires more than just `FROM node:latest` and `COPY . .`. This generator implements industry standards for security, performance, and maintainability:

::card-group
:::card{title="Multi-Stage Builds" icon="lucide:layers"}
Separates compilers, build tools, package managers, and devDependencies from the final runtime image. This dramatically shrinks image sizes from 1GB+ down to under 50MB and eliminates build tool vulnerabilities.
:::

:::card{title="Least Privilege Non-Root Execution" icon="lucide:shield-check"}
By default, Docker containers run as the root user (`UID 0`). Our generator automatically provisions dedicated non-root service accounts (`appuser:appgroup` or `nobody`) and assigns read/write permissions only where required.
:::

:::card{title="Active Docker Healthchecks" icon="lucide:heart-pulse"}
Enables the Docker daemon and container orchestrators to actively probe application liveness via HTTP endpoints or internal socket commands, preventing routing traffic to deadlocked or unready processes.
:::

:::card{title="Minimal Distroless / Alpine Bases" icon="lucide:minimize-2"}
Slim down attack vectors and CVE counts by utilizing minimal Alpine Linux or Google Container Tools Distroless images that omit package managers and shells from the production layer.
:::
::

## Understanding the Generated Artifacts

### 1. `Dockerfile`
The Dockerfile is organized in sequential stages:
1. **Build Stage (`builder`)**: Installs dependencies with cache mounts (`--mount=type=cache`), compiles binaries or bundles JavaScript, and prunes dev dependencies.
2. **Runtime Stage (`runner`)**: Starts from a stripped base image, creates a dedicated system user, copies only artifacts needed for execution, and sets strict file permissions.

### 2. `docker-compose.yml`
Generates a complete local development and staging orchestration setup with:
- Configured ports and restart policies (`unless-stopped`).
- Isolated internal network bridges.
- Optional persistence volumes for databases (PostgreSQL, MySQL, Redis).
- Environment variable injection and container dependency graphs (`depends_on`).

### 3. `.dockerignore`
Prevents local `node_modules/`, `.git/`, `.env` secrets, and IDE caches from being inadvertently copied into the container build context, speeding up upload times and protecting sensitive credentials.
